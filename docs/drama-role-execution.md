# 工作台 Agent 与节点执行

## 阶段一　作品与配置

作品保存负责总编的 Agent ID。新作品只有一个可选总编时自动绑定。有多个可选配置时，用户选择一次。历史会话继续保留实际运行的职责和模型快照；需要采用新版总编配置时新建会话。画布使用工作台 Agent 库里的具名配置，作品自由委派也从该库取人。「允许委派对象」为空时，协调 Agent 可以审核，不能派工。Orchestrator 可以选择已授权的 Manager 和 Worker，Manager 只能选择已授权的 Worker。退役配置退出新选择目录，原有稿件和执行记录保留。

Agent 页和节点历史可检查职责、实际版本、模型与推理等级。工作台提供 `GET /api/drama/protocol` 读取执行时使用的角色指令、交付指令、规则判断指令、工具分组、派工数量和校验回执上限。业务要求由用户在 Agent 职责、节点指令和输入/输出规则中调整。三种角色都可按需读当前绑定的 Skill 版本；公开网络和容器工具属于 Worker。自由委派的 Worker 使用自己的授权，每次网络调用校验当前有效授权。画布入队时固定授权 ID 或无授权。节点等待上游期间新开、撤销后重开的授权只能供后续新轮使用；旧版等待记录若未存授权 ID，按无权派发。已经派发的尝试继续校验其原授权是否有效。

## 阶段二　拆分、退修和放行

画布保存 `agentId`；运行时固定本轮节点与负责人版本。Worker 接收一个单独的 Attempt。画布 Orchestrator 使用独立会话，只有作品总编对话可以调用整图管理工具。Manager 和 Orchestrator 可以根据输入和节点指令直接提交审稿结论，也可以使用 `studio_split` 将最多 16 项分工一次性持久化到同一父任务下。每项使用独立会话。子任务收到祖先任务指令与已锁定的原始输入。分工全部持久化成功后才唤醒调度器。Worker 并发数由现有持久调度器限制。

全部直接子任务完成后，系统只向该父任务的协调者投递验收。协调者可分段阅读子稿，提交完整交付内容、退回整节点，或只退修一项直接子任务。重跑失败或退修的 Worker 会保留旧 Attempt 和候选正文。成功同级任务不会随之重新生成。网络调研记录随对应 Worker 和 Attempt 保留。协调者提交后，画布继续执行节点配置的输出检查。配置人工审核时，下游等待用户对确切稿件版本放行。

暂停节点会逐层暂停后代的待派工作；运行中的 Worker 在模型安全点暂停。恢复继续原尝试，进程意外终止则从持久状态新建恢复尝试。停止或替换节点时取消所属子树，独立运行继续。子任务的指令、负责人、版本、状态和尝试保存在 SQLite。`GET /api/drama/projects/:project/node-runs/:node/history` 读取本轮及后代可见的原生 DSH 消息与工具调用，连同成果版本和人工签核。每页 50 个事件，可用 `nextOffset` 续读。

## 回归

`tests/drama-role-tasks.test.ts` 使用命名的总编、两位设置不同的主编及各自编辑，覆盖同时派工、汇总、只重试失败分支、Agent 退修、人工审核和精确版本交接。中断测试重新打开真实 SQLite，检验已成功的同级结果原样保留。原生工具测试覆盖总编与 Manager 的 Skill 读取、自由 Worker 的网络调用和即时撤权。确定性测试使用隔离演示适配器；真实模型的判断、回复和工具选择受实际模型配置影响。


## 长篇材料与交稿

画布派工固定上游批准稿和资料版本，工作台按原文保存。投递正文与祖先指令合计超过 16,000 字符时，首轮只放每份输入开头和完整长度。三种角色都可以用 `drama_read_input` 按页读取，或用关键词定位。分页结果包含下一页位置。上下文压缩后会重新提供读取入口。Worker 交稿和协调者汇总保留完整正文，普通模型请求沿用 DSH 模型的输出配置。自然语言规则针对完整材料独立判断，模型无法容纳或核实材料时，检查结果显示原因并阻止交接。
