# 从作品总编对话管理工作流

在作品中打开「总编对话」，用「发送消息」要求总编管理当前作品的画布。新建对话保留同一部作品的画布和运行记录。每个对话保存自己的消息、操作回执和画布草案。

| 给总编的说明 | 可见结果 |
| --- | --- |
| 用分集模板搭建流程，润色交给编辑 | 总编先查询当前模板和具名 Agent，再提议画布草案。回执显示模板版本、增改节点和连线。打开草案可编辑节点、连线和配置。保存后更新本作品的同一张画布。 |
| 增加一位负责历史考证的主编 | 总编先提出具名 Agent 及职责。打开「配置此 Agent」，在工作台表单选择已配置的模型、推理等级、允许的下属或权限，保存后产生可复用配置。需要让其他 Agent 委派给它时，在相应上级的允许委派对象中选入。 |
| 把对白审核移到润色之后 | 草案只修改指定节点或边，沿用其他分支。新增连线产生环会被拒绝。保存基于提议时的图版本。如果期间有人改图，当前画布和总编草案均保留，可参考新图重新提议。 |
| 执行分集大纲和下游节点 | 工作台按当前图版本启动指定的运行。回执包含运行 ID，节点按依赖、输入检查和放行条件逐个进入可执行状态。追加运行继续单独入队。 |
| 现在卡在哪里 | 总编可查各轮次、节点的实际负责人、等待原因、稿件与任务引用。运行概览逐页显示节点，对每个节点先给出至多三项失败、暂停、等待验收或退回的子任务。同一轮内可按节点继续分页查看具体负责人和原因。不涉及创作稿的人工签核。 |
| 停止刚才启动的这一轮 | 总编根据运行 ID 停止该轮。尚未派发的节点立即停止派发，工作台对活跃任务及其下属发出取消请求。停止完成后回执显示「已停止」。已放行的稿件、其他轮次及其任务保留。 |

若模板的节点 ID 与现有节点冲突，套用时会为复制的节点选择新 ID，并保留模板内部连线。已有节点仍可在编辑草案时显式调整。身份或目标范围有歧义时，总编提示进一步说明。

## 持久化与权限

工作台将总编工具挂在作品编辑会话的根 Orchestrator。每次工具调用同时检查运行、Agent 和当前交付的用户消息。画布 Orchestrator 节点与子任务的消息、输出、验收反馈均不具备作品画布管理权限。项目 ID 来自会话绑定，模型无法传入其他作品 ID。草案的确认和放弃只通过受现有工作台身份、来源与 CSRF 校验保护的人工入口进行。

操作回执保存在 SQLite 的 `drama_editor_receipts`，与作品及对话关联。画布提议包含基础版本及完整候选图。新 Agent 建议只保存名称、角色和职责，模型、权限和下属以用户保存的配置为准。用户确认时与人工画布保存共用校验和版本检查。工作流启动与回执进入同一事务，重复处理同一次消息中的同一操作会复用其回执。每次图运行固定图版本；用户修改当前图后，正在执行的轮次继续使用已经锁定的配置与资料。

整轮停止把请求时间记入运行，将未完成的节点标为「正在停止」。调度器依据持久状态恢复停止事宜，所有任务确认终止后写入完成时间。取消发生错误时记录原因，用户可让总编重试该轮。节点图中的人工批准始终针对具体稿件版本，作品总编的工具不提供代签入口。

## 验证

`tests/drama-editor-control.test.ts` 覆盖模板节点 ID 冲突、人工修改草案、并发写入时保留草案、重启后读取原草案、跨作品和角色的权限检查、运行回执幂等、局部停止，以及取消意图在故障重启后继续生效。HTTP 集成测试以本地测试模型通过 DSH 的模型工具协议访问工作台，依次由普通总编消息发起目录查询、模板提议、启动、监控、停止和新角色建议，检查确切运行、草案回执、人工选择的模型和允许委派对象。
